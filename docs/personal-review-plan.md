# 개인용 작업 회고·개선 계획

목표는 작업 이력에서 근거를 확인하고 다음 작업에서 바꿀 행동을 기록하는 것이다.
첫 사용자는 개인이며, 기존 Streamlit·로컬 로그 수집을 유지한다.

## 첫 버전

1. 세션을 작업에 수동으로 묶는다. 에이전트와 세션 ID의 조합으로 식별하며 한 세션은 한 작업에 속한다.
2. 작업 유형, 사용자가 평가한 결과, 잘된 점, 막힌 점, 다음 행동을 저장한다.
3. 구조화된 도구 호출·결과에서 동일 요청 3회 이상의 실패와 동일 파일 조회 요청 3회 이상을 찾는다.
4. 같은 세션·모델의 시간순 사용량에서 입력이 3배 이상이고 4,096토큰 이상 증가한 구간을 표시한다.
5. 신호의 근거를 선택해 원문을 확인하고 개선 항목으로 기록한다. 직접 입력도 지원한다.
6. 개선 항목은 실천 예정·적용함·보류로 관리하고 적용 시각을 남긴다.

## 구현 경계

- SQLite에는 작업·메모·개선 항목·로그 위치만 저장한다. 원본 로그와 원문 내용은 복사하거나 수정하지 않는다.
- 파일이 없어져도 저장한 기록을 유지한다. 근거가 현재 스냅샷과 일치할 때 원문 조회를 제공한다.
- 조회만으로 DB를 만들지 않는다. 첫 저장 시 스키마 버전 1을 생성한다.
- 회고 화면은 저장된 전체 작업과 연결 세션 전체 이력을 사용한다. 기간 분석 필터와 적용 범위를 명시한다.
- 신호는 확인할 후보이며 생산성 점수나 성공 판정이 아니다. 알 수 없는 도구 결과·토큰·모델은 추정하지 않는다.
- 구조화되지 않은 도구 호출, 실행 중 결과, 지원되지 않는 스키마는 반복 실패 분석에서 제외한다.

## 검증 기준

- 재시작 후 회고·작업 묶음·개선 상태가 유지된다.
- 같은 세션 ID를 가진 다른 에이전트를 혼동하지 않고, 중복 연결 실패 시 기존 기록이 보존된다.
- 중복 로그를 신호에 중복 계산하지 않는다. 성공·미확인 결과를 실패로 분류하지 않는다.
- 모델이 다른 사용량과 시각·입력이 없는 사용량으로 증가 신호를 만들지 않는다.
- 실제 Streamlit 진입점에서 회고 생성·수정·신호 기록·상태 변경·원문 조회를 합성 데이터로 검증한다.
- 기존 테스트를 실행하고 `graphify update .`로 코드 그래프를 갱신한다.

## 이번 작업에서 확장한 범위

1. 프로젝트 자동 식별과 명시적 폴더·세션 연결을 제공한다. 미연결 세션은 숨기지 않는다.
2. 프로젝트별·프로젝트 간·작업에 묶인 세션의 통계를 같은 계산 서비스로 제공한다.
3. 프로젝트 내부 에이전트 지침을 경로·적용 폴더·해시와 함께 읽고 기준 프로젝트와 비교한다.
4. 독립 stdio MCP 서버로 통계·지침·세션 근거와 분석 요청 인수·보고서 저장 도구를 제공한다.
5. 기존에 연결한 에이전트가 분석을 수행하고 근거를 참조한 보고서·개선안을 반환한다.
6. 앱에서 결과를 검토하고 개선 항목을 채택·추적한다. 멈춘 요청의 재시도는 이전 소유 토큰을 무효화한다.

프로젝트·분석 기록은 별도 SQLite에 보관한다. MCP와 UI의 통계 계산·저장소를 공유하고
요청 당시 통계·지침 버전으로 근거를 보존한다. 실제 stdio 연결에서 조회부터 결과 저장까지 테스트한다.
연결 방식과 공개 도구 계약은 [MCP 안내](mcp.md)를 따른다.

## 이후 후보

분석 요청의 자동 에이전트 실행, 비슷한 후속 작업의 변화 추적, 지침 변경안 적용은 이후 후보다.
팀 운영·클라우드·에이전트 실행 제어·설정 자동 수정은 이번 범위에 포함하지 않는다.
