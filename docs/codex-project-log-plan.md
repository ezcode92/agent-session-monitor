# Codex 전용 전환과 프로젝트 작업 로그 개선 분석

요청 기준: 2026-09-12. Claude `missing path`와 AGY `usage_unavailable`의 파서를 새로 지원하지 않고 해당 수집 기능을 deprecated 처리한다. 기존 사용자 데이터를 삭제하지 않는다.

## 구현 순서와 수용 기준

| 단계 | 구현 | 수용 기준 |
|---|---|---|
| 1. Codex 전용 수집 | 기본 설정·직접 설정·설정 갱신을 동일 정규화 함수로 제한 | Claude·AGY 경로를 탐색/파싱/진단하지 않음. 기존 Codex 경로 유지. 레거시 경로는 `deprecated_paths`로 보존 |
| 2. 프로젝트 로그 분석 | 단일 프로젝트와 선택 기간/작업 세션의 정규화된 Codex 로그를 로컬 분석 | 다른 프로젝트·비활성 에이전트 근거 제외, 종료 시각 미포함, 누락·잘림과 근거 부족 명시 |
| 3. 실행 가능한 개선안 | 반복 실패·명시적 테스트 실패·반복 조회·입력 급증·긴 관측 요청 구간 | 후보별 우선순위·근거·실천 제안·검증 방법 제공. free-text error·unfinished·토큰 크기만으로 실패/낭비 단정 금지 |
| 4. UI·저장 | 실행/저장 버튼, 범위·근거·검증 방법 표시, 채택·상태 관리·JSON | 저장 실패 시 성공 메시지 없음. 동일 결과 재분석·재채택 중복 방지. 앱 재실행 후 상태 보존 |
| 5. MCP | `analyze_project_work_logs` 읽기 전용 도구와 기존 심층 분석 요청에 로그 근거 포함 | 모델 API 호출 없이 조회. 결과 전용 MCP에는 새 도구·원문 미리보기 미노출. 기존 보고서 계약 유지 |
| 6. UI 정리 | 적용되지 않는 전역 필터 비활성화, 손상된 boolean 필터 상태 초기화, Codex 경로만 설정, 진단 유형 요약·필터·바로가기 | 화면 이동 후 유효한 선택 유지. 기존 설정 저장·실패·복구 테스트 통과 |
| 7. 검증·병합 | 단위 테스트·Streamlit AppTest·stdio MCP·합성 브라우저 점검 | 실제 실행 결과 확인 후 PR을 `main`에 squash 병합. 운영 서버 배포와 Git 병합을 구분 |

## 판정과 적용 범위

반복 실패는 같은 도구·입력 서명의 명시적 실패 3건 이상을 같은 프로젝트의 세션 간 합산한다. 테스트 명령은 명시적 실패 1건부터 재현·회귀 검토 후보로 제공한다. 반복 조회는 같은 세션에서 같은 조회 입력 3회 이상, 입력 급증은 같은 세션·모델에서 3배 이상이면서 4,096토큰 이상 증가한 경우다. 긴 요청은 선택 기간과 겹치는 관측 구간 900초 이상이다. 이 임계값은 검토 후보 기준이지 오류·타임아웃·품질 판정이 아니다.

최근 이벤트 10,000건·사용량 10,000건·요청 2,000건을 분석한다. 최대 후보 30개, 후보별 근거 20개로 반환하며 전체/분석/표시 건수와 잘림 여부를 기록한다. 동일 이벤트·명시적 호출 ID는 중복 집계하지 않고 알 수 없는 사용량은 null로 유지한다.

기본 분석은 명시적 버튼/도구 호출 때만 실행한다. 로컬 규칙으로 판단하기 어려운 프로젝트 지침·작업 내용의 심층 해석은 기존 Codex/MCP 분석 요청에 근거를 제공한다. 연결한 Codex가 실행되기 전에는 심층 분석을 완료했다고 표시하지 않는다.

## 데이터와 배포

원본 로그·프로젝트 파일은 읽기 전용이다. 기존 SQLite 스키마와 과거 회고/분석/연결 기록을 보존한다. 보고서에는 근거 미리보기가 저장되므로 JSON 외부 공유 전 민감 정보를 검토해야 한다. 결과 전용 MCP는 근거의 로컬 경로·레코드 위치·미리보기를 제거하지만 사용자가 작성한 보고서 본문까지 자동 정화하지 않는다.

`main` 병합은 운영 서버 재시작을 뜻하지 않는다. 운영 프로세스의 갱신/재시작 여부와 실제 사용자 로그로 새 분석을 실행했는지는 별도 검증 범위다. 테스트에서는 합성 로그와 임시 DB만 사용한다.
