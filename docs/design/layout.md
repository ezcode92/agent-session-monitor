# 레이아웃·정보 밀도

[디자인 안내](README.md)

데스크톱에서는 표·차트 비교를 우선하고, 모바일에서도 같은 데이터와 핵심 조회·입력을 제공한다.
페이지 최대 폭은 76rem, 폼의 최대 폭은 48rem이다. 짧은 입력을 넓은 표의 폭으로 늘리지 않는다.
읽기 폭을 제한한 폼은 표와 같은 왼쪽 기준선에 둔다.

## 순서와 간격

- 페이지 제목·설명·적용 범위 → 핵심 작업 → 보조 상세 순서로 구성한다.
- 큰 소개 영역, 중첩 카드, 장식 배지, 불필요한 설명을 추가하지 않는다.
- 4px 단위 간격을 역할에 맞춰 사용한다. 페이지 바깥 gutter는 한 컨테이너가 소유한다.
- 상단 진입 여백에는 native 메뉴 높이를 포함해 제목이 고정 도구 모음에 가려지지 않게 한다.
- 형제 영역 간격은 부모 gap, 컨트롤 내부 간격은 padding으로 관리한다.
- 지표는 콘텐츠가 들어갈 최소 폭을 기준으로 자동 줄바꿈한다. 남는 폭을 채우려고 지표를 추가하지 않는다.
- 선택값·오류·현재 상태·필수 입력은 항상 확인 가능해야 한다. 원문·출처·보조 통계는 펼침으로 제공한다.

## 반응형 기준

배치의 원본은 [styles.css](../../src/agent_monitor/ui/styles.css)다.
지표는 최소 12rem의 자동 그리드로 구성하고, 48rem 이하에서는 여러 열의 입력·행동을 세로로 배치한다.
이 전환점은 긴 한국어 라벨과 3~4개 조작을 한 줄에서 읽기 어려워지는 폭을 기준으로 한다.
미디어 조건을 CSS와 Python·JavaScript 양쪽에 중복 구현하지 않는다.

- 좁은 화면은 Streamlit의 접을 수 있는 사이드바로 탐색한다. 페이지 이동은 링크, 값 선택은 입력으로 구분한다.
- 제목과 보조 정보는 자연스럽게 줄바꿈한다. 기기명 판별·고정 화면 축소·글자 축소로 맞추지 않는다.
- 표·차트·코드·구조화 원문에만 내부 가로 스크롤을 허용한다. 일반 본문의 넘침은 숨기지 말고 고친다.
- 데이터 표의 세션 ID·부모 ID 선택과 상세 내용은 좁은 화면에서도 제공한다. 목록과 상세는 세로 흐름으로 배치한다.
- 주요 조작은 최소 44px, 터치 환경에서는 48px을 확보한다. 고정 CTA는 사용하지 않는다.
- 낮은 가로 화면·가상 키보드·확대에서도 자연스러운 세로 스크롤을 유지한다.

모바일의 정보 행·입력 상태·주요 행동 분리는 [Toss ListRow](https://tossmini-docs.toss.im/tds-mobile/components/ListRow/list-row-overview/),
[TextField](https://tossmini-docs.toss.im/tds-mobile/components/TextField/text-field/),
[BottomCTA](https://tossmini-docs.toss.im/tds-mobile/components/BottomCTA/Single/)를 출처로 가진 참고 지침에서 채택했다.
Toss의 브랜드색·폰트·패키지·바텀시트를 도입한 것은 아니다.
