# 화면 계약

[디자인 안내](README.md)

공통 application shell은 native sidebar 탐색 → 페이지 제목·설명·적용 범위 → 작업 영역이다.
아래 순서는 시각적 우선순위이며 접힌 상세는 기본 화면의 작업을 밀어내지 않는다.

| 화면·URL | 기본 노출과 상세 | 완료 조건 |
|---|---|---|
| 개요 `/` | 세션·요청·전체 토큰·평균 작업 시간 → 주요 추이 → 상위 요청. 나머지 지표·캐시 차트·세션 표는 펼침 | 현재 사용량을 파악하고 작업 이력으로 이동 |
| 작업 이력 `/history` | 검색·결과·페이지 → 세션/부모 ID 선택 → 요청·로그·실시간·회고 중 선택한 상세. 요청 보기에는 세션 토큰·요청당 평균·요청별 토큰 표·선택 요청의 도구 호출과 결과 | 같은 에이전트의 올바른 요청·도구 근거를 조회하거나 회고를 저장 |
| 회고·개선 `/reviews` | 작업/개선 보기 → 작업 요약·결과 → 입력·문제 신호·개선 상태 | 회고 또는 개선 상태를 실제 저장하고 결과 확인 |
| 에이전트 분석 `/agent-analysis` | 범위·대상·통계 → 요청 작성 → 보조 연결 관리 → 요청 상태·결과·개선안 | 요청 전달, 근거 있는 보고서 확인, 개선안 채택 |
| 기간 분석 `/analytics` | 비교 기준·집계 단위 → 기준별 사용량 → 작업 시간·전체 추이·분포 → 내보내기 | 동일 기간·집계 단위의 차트와 데이터를 비교·내보내기 |
| 오케스트레이션 `/orchestration` | 요약·관계 경고 → 루트·계층 표 → 세션 상세·요청 타임라인 → 관계 근거 펼침 | 명시적 부모·자식 관계와 요청 간 공백·겹침 확인 |
| 설정 `/settings` | 경로·시간대 입력 → 저장·복원·재스캔 → 수집·설정 진단 | 변경 저장 또는 오류 원인을 확인하고 재시도 |

회고는 저장한 작업과 연결 세션 전체를 사용하며 공통 필터를 적용하지 않는다.
에이전트 분석은 공통 필터 중 기간만 사용하고 프로젝트·작업 선택은 화면 자체의 범위를 따른다.
설정은 전체 수집 설정과 진단을 표시한다. 나머지 화면은 기존 기간·에이전트·프로젝트·모델 집계 계약을 따른다.

빈 데이터·검색 결과 없음·필터 결과 없음에는 원인에 맞는 다음 행동을 안내한다.
에이전트 분석의 실패·다시 대기시키기와 설정 복원 확인은 기본 화면에서 접근 가능해야 한다.
지표·경고 수·상태·보고서 내용은 서비스가 제공한 실제 데이터만 사용한다.

모바일에서도 목록 위·상세 아래의 흐름을 유지한다. 세션 상세의 선택한 보기만 실행하고,
완료된 Codex 세션은 실시간 추적하지 않는다. 일시정지는 기존 수집 버퍼를 보존한다.

MCP API·SQLite·수집·집계 규칙을 변경하지 않는다. 이전에 제거한 직전 기간 비교·Graph CSV/Markdown,
새 분석 기능·필터 URL 공유·브라우저 종료 후 초안 복원은 이번 적용 범위가 아니다.
