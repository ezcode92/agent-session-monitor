# Agent Session Monitor

Codex, Claude Code, Antigravity 세션 로그를 읽고 개인 작업을 회고·분석하는 로컬 Streamlit 대시보드이자 stdio MCP 서버입니다. 프로젝트별·프로젝트 간 통계와 에이전트 지침을 비교하고, 연결한 에이전트의 분석 보고서를 실천할 개선 항목으로 관리합니다. 앱 자체는 원본 로그를 수정하거나 외부 LLM을 호출하지 않으며, 회고·프로젝트 연결·분석 기록은 로컬 SQLite에 보관합니다. MCP로 데이터를 조회하는 에이전트에는 해당 클라이언트의 데이터 전송·과금 설정이 적용됩니다.

Antigravity는 `~/.gemini/antigravity/brain`, `~/.gemini/antigravity-cli/brain`, `~/.gemini/antigravity-ide/brain`을 기본 수집 경로로 사용합니다. 기존 설정의 설치 폴더도 재귀 탐색하므로 계속 사용할 수 있습니다. 실제 로그는 `brain/<세션 ID>/.system_generated/logs/transcript.jsonl`이며, `transcript_full.jsonl`과 chunk 사본은 중복 수집하지 않습니다. 이 구조는 [공식 Hooks 문서](https://www.antigravity.google/docs/hooks) 및 [IDE Hooks 문서](https://antigravity.google/docs/ide/hooks)에 명시되어 있습니다.

`source_path`는 대표 원본 파일이고 `sources`는 병합된 모든 원본 파일 목록입니다. 작업 이력에서는 경로를 상세 영역에 한 번씩 표시합니다.

## 실행

Python 3.12 이상과 `uv`가 필요합니다. 테이블 셀 선택을 위해 Streamlit 1.63 이상을 사용하며 `uv sync --locked --group dev`로 검증된 의존성을 설치할 수 있습니다. Windows에서는 패키지 캐시와 Python 설치 위치를 작업 폴더 안에 두면 권한 또는 전역 캐시 잠금 문제를 피할 수 있습니다.

macOS/Linux에서는 저장소 루트에서 실행합니다.

```bash
uv sync --locked --group dev
uv run --locked streamlit run app.py --server.address 127.0.0.1 --server.port 8501
```

Windows PowerShell 예시입니다.

```powershell
$env:UV_CACHE_DIR="$PWD\.tools\uv-cache"
$env:UV_PYTHON_INSTALL_DIR="$PWD\.tools\python"
.\.tools\bin\uv.exe run streamlit run app.py --server.address 127.0.0.1 --server.port 8501
```

일반 `uv`가 PATH에 있다면 같은 환경 변수 설정 후 다음 명령을 사용할 수 있습니다.

```powershell
uv run streamlit run app.py --server.address 127.0.0.1 --server.port 8501
```

가상환경을 이미 만들었다면 다음 명령으로도 실행할 수 있습니다.

```powershell
.venv\Scripts\python.exe -m streamlit run app.py --server.address 127.0.0.1 --server.port 8501
```

`python app.py`는 `src` 패키지 import를 지원하는 엔트리포인트입니다. 일반적인 대시보드 실행은 위 Streamlit 명령을 사용합니다.

브라우저에서 `http://127.0.0.1:8501`을 엽니다.

## 화면

사이드바의 페이지 링크로 화면을 이동하며 각 화면의 URL을 직접 열 수 있습니다. 기간·필터와 주요 검색·선택값은 같은 브라우저 세션에서 화면을 오가도 유지됩니다. 오른쪽 위 메뉴에서 시스템 설정·라이트·다크 테마를 선택합니다. 화면별 필터 적용 범위는 제목 아래에 표시합니다.

틸 강조색, 공통 글자·간격, 좁은 화면의 세로 배치를 사용합니다. 개요는 핵심 지표를 먼저 보여주고 보조 지표·캐시 차트·세션 표는 펼침에서 확인합니다. 차트 아래의 데이터 펼침은 차트와 같은 집계 또는 원자료를 제공합니다. 프로젝트 전용 기준과 출처는 [디자인 안내](docs/design/README.md)에 있습니다.

- 개요: 전체·입력·출력 토큰, 요청당 평균 입력·출력 토큰과 작업 시간을 표시합니다. 입력·출력·캐시 차트는 행 개수가 아닌 실제 토큰 합계를 사용합니다.
- 작업 이력: 핵심 열만 표시하며 테이블의 세션 ID를 선택하면 아래 상세가 바뀝니다. 부모 ID는 같은 에이전트의 부모 상세를 엽니다. 요청 CSV와 로그 원문 조회는 상세에서 제공합니다.
- 실시간 로그: 선택 로그를 1초마다 확인합니다. Codex 상태가 `complete` 또는 `completed`이면 추적을 중단합니다. 추적 중 완료되면 마지막 이벤트를 유지하며, 세션 재개 후에는 수동 새로고침으로 추적을 다시 시작할 수 있습니다. 일시정지는 표시만 멈추고 수집 버퍼는 유지합니다.
- 기간 분석: 에이전트·모델·출처별 사용량을 일별·주별·월별로 비교합니다. 주는 월요일, 월은 1일 기준입니다. 분석 CSV/Markdown에는 같은 집계 단위가 적용되며 직전 동일 기간 비교는 제공하지 않습니다.
- 설정: 수집 경로와 파서·설정 진단을 표시합니다. 사용하지 않는 `data_quality`·`data_status` 컬럼과 처리 과정은 제거했습니다.
- 회고·개선: 작업 이력의 세션 보기에서 `회고`를 선택해 작업을 만들거나 기존 작업에 연결합니다. 여러 세션을 묶고 결과·잘된 점·막힌 점·다음 행동을 저장하며, 개선 항목의 실천 예정·적용함·보류 상태를 관리합니다. 저장한 전체 작업과 연결 세션 전체 이력을 사용하므로 사이드바 기간·모델 필터는 적용하지 않습니다.
- 에이전트 분석: 프로젝트별·프로젝트 간·작업 세션별 분석을 요청합니다. 프로젝트 통계와 에이전트 지침 원문·차이를 확인하고, MCP로 연결한 에이전트가 저장한 보고서와 개선 제안을 검토합니다. 프로젝트 정보가 없는 세션은 폴더에 수동 연결할 수 있습니다. 통계에는 사이드바 기간을 적용하고 에이전트·모델 필터는 적용하지 않습니다.
- 오케스트레이션: 임의 깊이의 하위 세션과 직접·하위·전체 토큰을 표시합니다. 타임라인은 요청별 관측 구간을 나눠 요청 사이 공백을 보존합니다. Graph CSV/Markdown은 제공하지 않습니다.

작업 시간은 `시:분:초`로 표시하며 24시간 이상도 누적 시간으로 표현합니다. CSV의 원본 시간 값은 초 단위를 유지합니다. 차트 제목 아래에는 설명을, 주요 지표와 테이블 헤더에는 툴팁을 제공합니다.

이전 환경에서 실제 Codex 로그와 Antigravity CLI의 356개 transcript(요청 868건, 이벤트 70,953건)를 확인했습니다. AGY의 `created_at`, `step_index`, `USER_INPUT`을 읽어 요청과 로그를 표시합니다. 이 표본에는 토큰·모델·부모 관계 정보가 없어 추정하지 않습니다. 개별 step의 `DONE`은 세션 완료로 간주하지 않습니다. Claude 실제 샘플은 아직 확보하지 못했습니다. 최신 환경의 실사용 통합테스트 결과는 아래 검증 현황에 별도로 정리했습니다.

토큰 또는 캐시 필드가 로그에 없으면 0으로 바꾸지 않고 `—`로 표시합니다. 지원되지 않는 Antigravity 스키마는 진단으로 드러납니다.

선택 로그는 1초 간격으로 변경 여부를 확인하지만, 변경된 큰 파일을 다시 파싱하는 동안 화면 반영에는 처리 시간이 추가될 수 있습니다.

## 개인 작업 회고

회고 데이터는 첫 저장 시 `.agent-monitor/reviews.sqlite3`에 생성됩니다. `AGENT_MONITOR_REVIEW_DB`로 위치를 바꿀 수 있습니다. SQLite에는 작업·메모·개선 항목과 근거 위치만 저장하며 원문을 복사하지 않습니다. 로그가 이동·삭제되어도 회고는 유지되고, `회고·개선 JSON 내보내기`로 기록을 내보낼 수 있습니다.

문제 신호는 동일한 도구 요청의 확인된 실패 3회 이상, 동일한 파일 조회 요청 3회 이상, 같은 세션·모델에서 입력이 3배 이상이면서 4,096토큰 이상 증가한 경우입니다. 지원되는 구조화된 메타데이터만 사용하며 일반 메시지의 오류 표현으로 실패를 추정하지 않습니다. 근거 원문은 버튼을 눌렀을 때 읽습니다. 신호가 없다고 문제가 없다는 뜻은 아니며, 세션 완료 상태·토큰·시간으로 작업 성공이나 생산성을 판정하지 않습니다.

첫 버전의 범위와 이후 후보는 [개선 계획](docs/personal-review-plan.md)에 정리했습니다.

## MCP 서버와 에이전트 분석

```bash
uv run --locked python mcp_server.py
```

앱은 별도 화면 없이 stdio MCP 서버로 실행할 수 있습니다. 연결한 에이전트에 프로젝트 통계·지침 비교·세션 근거를 제공하고, 분석 보고서와 개선 제안을 돌려받습니다. 분석 요청 생성만으로 에이전트가 자동 실행되지는 않으며, 분석에는 연결한 에이전트의 데이터 전송·과금 설정이 적용됩니다.

프로젝트 연결과 분석 기록은 `.agent-monitor/analysis.sqlite3`에 저장합니다. `AGENT_MONITOR_ANALYSIS_DB` 또는 서버의 `--analysis-db`로 경로를 바꿀 수 있으며 UI와 MCP에서 동일한 파일을 사용해야 합니다. 시작 명령·Codex 연결·도구 목록·보고서 형식은 [MCP 연결 안내](docs/mcp.md)에 있습니다.

MCP 통계 조회와 분석은 매 코딩 작업마다 실행하지 않고, 사용자가 회고·분석·프로젝트 비교를 명시적으로 요청할 때 수행하는 운영 방식을 권장합니다. 연결 시 도구 목록을 확인하는 것은 실제 로그 조회와 다릅니다. 명시적 요청 여부를 서버가 강제하는 기능은 없으므로 연결한 에이전트의 지침과 클라이언트 승인 설정으로 제한해야 합니다.

## 검증 현황과 제한 (2026-09-09)

- 자동 회귀 테스트: **135개 통과**. SQLite 회고·분석 저장, 지침 범위, 근거 검증, Streamlit 화면, 실제 stdio MCP 프로세스와 화면 이동·저장 실패 후 복구를 포함합니다.
- 디자인 적용 검증: 합성 데이터로 7개 화면 × 7개 화면 크기 × 라이트·다크의 **98개 조합**을 검사했습니다. 키보드 탐색·뒤로 가기·테마 선택과 주요 화면의 200% 글자 확대도 확인했습니다. 실기기·스크린리더 및 실제 브라우저 400% 확대는 미검증입니다.
- 실사용 통합테스트: 실제 Codex 12개·Antigravity 27개 세션과 탐지된 프로젝트 7개로 로컬 앱을 실행했습니다. MCP 도구 13종과 프롬프트 조회를 호출하고, 화면 요청 생성 → MCP 보고서 저장 → 개선안 채택·적용 → 브라우저 새로고침 후 유지까지 확인했습니다.
- 안전성: 다른 프로젝트의 근거 원문 조회, 중복 인수, 허위 근거 ID, 잘못된 인수 토큰과 완료 결과 재제출을 거부했습니다. 원본 로그는 읽기 전용으로 사용했고 테스트 저장은 임시 DB로 격리했습니다.
- 제한: 해당 환경의 Antigravity 세션 27개는 프로젝트 미연결 상태였으며 수동 연결이 필요합니다. Claude 실제 로그, 모바일 화면, 클라이언트에 등록된 Codex 커넥터와 무인 에이전트 실행은 이번 실사용 테스트에 포함하지 않았습니다.
- 남은 UI 확인 사항: 개선 상태 드롭다운의 마우스 자동 조작에서 화면 밖 옵션 문제가 있었으며 키보드 선택·저장은 성공했습니다. 원인은 아직 진단하지 않았습니다.

검증 범위·과거 벤치마크·한계는 [검증 기록](docs/validation.md)을 참고하세요. 로컬 로그·DB·실사용 스크린샷은 저장소에 포함하지 않습니다.
